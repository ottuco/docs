# Search & Filter Payments

Every [plugin](/business/plugins) in the Ottu Dashboard has a **Transactions** table. This page shows how to see which transactions are paid and which are not, how to find one transaction, and how to list the payment links created by one user or processed through one [connector](/business/payments/gateways). Administrators can also [choose the filters and search fields](#choose-the-filters-and-search-fields) that every transactions table offers.

**Who can do it:** any dashboard user. You only see the transactions you are allowed to see: if some are missing, see [Why can't I see all the transactions?](/business/users-and-access/transaction-visibility)

## How can I see which transactions are paid and which are not?

<StepShow>

<Step image="/img/business/payment-management/export-sidebar.png" spot="19,53,42,13" alt="The dashboard sidebar with Payment Request open and Transactions selected">

In the Ottu Dashboard sidebar, open the plugin, for example **Payment Request**, and click **Transactions**.

</Step>

<Step image="/img/business/payment-management/export-toolbar.png" spot="72.8,25.8,21.2,31" alt="The Filter button above the transactions table">

Click **Filter** at the top right of the table.

</Step>

<Step image="/img/business/dashboard/state-paid.png" spot="3.2,67.5,90,15.3" alt="The State filter open, with Paid in the list">

In **State**, choose:

- **Paid** to see the paid transactions;
- **All Unpaid** to see every transaction that is not paid. It covers the states Created, Pending, Attempted, Failed, Expired and Unavailable.

</Step>

<Step image="/img/business/payment-management/filter-panel.png" spot="22.4,85.6,27,10.6" alt="The Search button at the bottom of the Filter panel">

Click **Search**.

</Step>

</StepShow>

The table now shows only those transactions. To see everything again, click **Filter** and then **Reset**.

**State** takes one value at a time. You can also choose a single state, such as **Expired** or **Canceled**. Canceled transactions are not part of **All Unpaid**. See [Transaction States](/business/payment-management/transaction-states) for what each state means.

If there is no **State** filter, an administrator has removed it: ask them to [add it back](#choose-the-filters-and-search-fields).

## How do I filter the unpaid transactions and export them?

<StepShow>

<Step image="/img/business/payment-management/export-toolbar.png" spot="72.8,25.8,21.2,31" alt="The Filter button above the transactions table">

Open the plugin's **Transactions** table and click **Filter**.

</Step>

<Step image="/img/business/dashboard/state-unpaid.png" spot="3.2,79.6,90,15.3" alt="The State filter open, with All Unpaid at the end of the list">

In **State**, choose **All Unpaid**, then click **Search**.

</Step>

<Step image="/img/business/payment-management/export-toolbar.png" spot="39,26,33,31" alt="The Export Transactions button above the transactions table">

Click **Export Transactions** above the table.

</Step>

<Step image="/img/business/payment-management/export-options.png" spot="5,69,32,16" alt="The export options with Select file type: CSV or XLSX">

Under **Select file type**, choose **CSV** or **XLSX**, then click **Export**.

</Step>

<Step image="/img/business/payment-management/generated-reports.png" spot="81,23,9.5,16.5" alt="The Generated Reports table with the Download column">

The **Generated Reports** page opens. When your export shows a download icon, click it to get the file.

</Step>

</StepShow>

The file contains only the transactions the table was showing. See [Export Transactions](/business/payment-management/export-transactions) for more, including what to do when an export is slow.

## How do I find one transaction?

Use the search above the table. It searches one field at a time.

<StepShow>

<Step image="/img/business/payment-management/export-sidebar.png" spot="19,53,42,13" alt="The dashboard sidebar with Payment Request open and Transactions selected">

Open the plugin's **Transactions** table.

</Step>

<Step image="/img/business/dashboard/search-bar.png" spot="1.3,11.8,44.9,80.9" alt="The search above the transactions table: Select field, the Search box and the Search button">

In **Select field**, choose what you know about the payment, for example the customer's email.

</Step>

<Step image="/img/business/dashboard/search-bar.png" spot="46.5,11.8,40.9,80.9" alt="The search above the transactions table: Select field, the Search box and the Search button">

Type the value in the **Search** box. Part of the value is enough, and capital letters do not matter: `shop` finds `shopify`.

</Step>

<Step image="/img/business/dashboard/search-bar.png" spot="87.2,21.6,12.1,58.8" alt="The search above the transactions table: Select field, the Search box and the Search button">

Click the **Search** button.

</Step>

</StepShow>

### I only have the customer's name

Look in **Select field** for the customer's name fields, such as **First Name** or **Last Name**:

- If they are listed, choose one, type the name and click **Search**.
- If they are not listed, the search cannot use the name yet. Ask your account administrator to add the name fields as [search fields](#search-fields). An administrator chooses which fields the search offers, and none are set up by default.

Two other ways to find the payment:

- If your sidebar has **Express Search**, open it. It can search by order number, session ID, customer email, customer first name, customer last name and customer phone.
- Narrow the table with **Filter**, for example by the date the payment was created or by its **State**, and look through the shorter list.

## Choose the Filters and Search Fields

An administrator chooses which filters and search fields the transaction tables offer, in **Administration Panel** > **Search** > **Search Config**.

### Filters

Each row under **Filter Fields** adds one filter to every transactions table:

| Setting | What it does |
|---------|--------------|
| **Field** | The transaction field to filter on. Most transaction fields can be used, plus **Seen**, **Email Seen** and **Application** (the application that created the payment). |
| **Label** and **Label (Arabic)** | Optional. When **Label** is empty, the field's own name is shown. When only **Label (Arabic)** is empty, the dashboard in Arabic shows **Label**. |
| **Filter Type** | **Dropdown**, **Boolean**, **Date**, **Date Time** or **Amount Range**. When empty, Ottu picks the type that fits the field. |
| **Minimum Amount** and **Maximum Amount** | The range of the slider of an **Amount Range** filter. |
| **Order** | The position of the filter. |
| **Is active?** | Clear it to hide the filter without deleting it. |

By default there are filters for the created, modified and state-changed dates, the state, gateway, currency and initiator, and the **Seen** and **Email Seen** flags. A dropdown lists the values its field can have, for example your gateways, your users, or the applications found on your payments.

### Search Fields

Choose what the search box can search on:

- **Internal Fields**: select any of **Internal ID**, **Customer Email** and **Application**.
- **Search Fields**: add fields of your plugins, including custom fields.

A search matches part of the value and ignores case, so `shop` finds `shopify`. A plugin with its own entry in **Administration Panel** > **Search** > **Plugin Search Configs** uses that entry's search fields instead.
