Follow these steps to go from a new Android project to your first test payment with the Checkout SDK. For all options, see the full [Android Checkout SDK](android.mdx) documentation.

## Prerequisites

- Android 8 or higher (API version 26 or later).
- Your Ottu merchant domain, used as `merchantId`: the domain you send API requests to, without `https://` (for example `sandbox.ottu.net`).
- Your [API public key](../../getting-started/authentication.md#public-key), used by the app.
- Your [API private key](../../getting-started/authentication.md#api-key-auth), used only by your server. Never put it in the app.
- The [PG code](/glossary/#term-pg-code) (`pg_code`) of the payment gateway to pay with. See [Payment Methods](../payment-methods.md) to find yours.

## Create a Payment Session

Your server calls the [Checkout API](../checkout-api.mdx) with your [private key](../../getting-started/authentication.md#api-key-auth). The response contains the `session_id`; send it to the app together with the amount, because the Android SDK needs both.

## Integrate the Checkout SDK

<ol className="stepper">
  <li className="stepper-item">
    <strong>Add a container to your layout</strong>
    <div>
      In `activity_main.xml` (in the `res/layout` folder), add a `FrameLayout` with the ID `ottuPaymentView`. The checkout is shown inside it:
    </div>

    ```xml
    <FrameLayout
        android:id="@+id/ottuPaymentView"
        android:layout_width="match_parent"
        android:layout_height="wrap_content" />
    ```

  </li>
  <li className="stepper-item">
    <strong>Prepare your Activity</strong>
    <div>
      The Activity that shows the checkout must extend `AppCompatActivity`. Import the SDK and add a member for the `CheckoutSdkFragment`:
    </div>

    ```kotlin
    import com.ottu.checkout.Checkout
    import com.ottu.checkout.ui.base.CheckoutSdkFragment

    class MainActivity : AppCompatActivity() {
        private var checkoutFragment: CheckoutSdkFragment? = null
    }
    ```

    <div>Android Studio usually adds the other imports the next steps need.</div>
  </li>
  <li className="stepper-item">
    <strong>Initialize the SDK and show the checkout</strong>
    <div>Inside `onCreate`, build the configuration, initialize the SDK and put the returned fragment in the container:</div>

    ```kotlin
    val merchantId = "sandbox.ottu.net" // your Ottu merchant domain
    val sessionId = "" // the session_id from your server
    val apiKey = "" // your API public key
    val amount = 10.0 // the session amount

    val builder = Checkout
        .Builder(merchantId, sessionId, apiKey, amount)
        .logger(Checkout.Logger.INFO)
        .build()

    if (Checkout.isInitialized) {
        Checkout.release()
    }

    lifecycleScope.launch {
        runCatching {
            Checkout.init(
                context = this@MainActivity,
                builder = builder,
                successCallback = {
                    Log.e("TAG", "successCallback: $it")
                    showResultDialog(it)
                },
                cancelCallback = {
                    Log.e("TAG", "cancelCallback: $it")
                    showResultDialog(it)
                },
                errorCallback = { errorData, throwable ->
                    Log.e("TAG", "errorCallback: $errorData")
                    showResultDialog(errorData, throwable)
                },
            )
        }.onSuccess {
            checkoutFragment = it
            supportFragmentManager
                .beginTransaction()
                .replace(R.id.ottuPaymentView, it)
                .commit()
        }.onFailure {
            showErrorDialog(it)
        }
    }
    ```

    <div>
      `merchantId`, `sessionId`, `apiKey`, `amount` and the callbacks are required. To choose the payment methods shown, add [`formsOfPayment`](android.mdx#display-options). To start faster, pass the session details with [`setupPreload`](android.mdx#preloading).
    </div>
  </li>
  <li className="stepper-item">
    <strong>Release the SDK</strong>
    <div>Free the SDK's resources when the Activity closes:</div>

    ```kotlin
    override fun onDestroy() {
        super.onDestroy()
        if (isFinishing) {
            Checkout.release()
        }
    }
    ```

  </li>
</ol>

## Callbacks

The SDK calls `successCallback` when the payment succeeds, `cancelCallback` when the customer cancels, and `errorCallback` when something goes wrong. Add the dialogs used in `Checkout.init` to the same `MainActivity`:

```kotlin
private fun showResultDialog(result: JSONObject?, throwable: Throwable? = null) {
    val sb = StringBuilder()

    result?.let {
        sb.apply {
            append(("Status : " + result.opt("status")) + "\n")
            append(("Message : " + result.opt("message")) + "\n")
            append(("Session id : " + result.opt("session_id")) + "\n")
            append(("operation : " + result.opt("operation")) + "\n")
            append(("Reference number : " + result.opt("reference_number")) + "\n")
            append(("Challenge Occurred : " + result.opt("challenge_occurred")) + "\n")
            append(("Form of payment: " + result.opt("form_of_payment")) + "\n")
        }
    } ?: run {
        sb.append(throwable?.message ?: "Unknown Error")
    }

    AlertDialog.Builder(this)
        .setTitle("Order Information")
        .setMessage(sb)
        .setPositiveButton(
            android.R.string.ok
        ) { dialog, which ->
            dialog.dismiss()
        }
        .show()
}

private fun showErrorDialog(throwable: Throwable? = null) {
    if (throwable is SecurityException) return

    AlertDialog.Builder(this)
        .setTitle("Failed")
        .setMessage(throwable?.message ?: "Unknown Error")
        .setPositiveButton(
            android.R.string.ok
        ) { dialog, which ->
            finish()
            dialog.dismiss()
        }
        .show()
}
```

After a cancel or an error, initialize the SDK again, on the same session or a new one. See [Callbacks](android.mdx#callbacks) for the data each callback receives.

## Test a Payment

Run the app and pay with a test card for the gateway in your session's `pg_codes`. When the payment succeeds, `successCallback` is called.

- [Ottu Sandbox](../ottu-sandbox.mdx): a simulated gateway where the [test card](../ottu-sandbox.mdx#test-cards) decides the result.
- [Test Cards](../sandbox.mdx): test cards for each payment gateway's own sandbox.
