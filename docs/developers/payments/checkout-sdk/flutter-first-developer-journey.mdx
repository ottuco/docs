Follow these steps to go from a new Flutter project to your first test payment with the Checkout SDK, on Android and iOS. For all options, see the full [Flutter Checkout SDK](flutter.mdx) documentation.

## Prerequisites

- Android 8 (Android SDK 26) or higher, and iOS 15 or higher.
- A Flutter project. To create one, see [Create a new Flutter app](https://docs.flutter.dev/reference/create-new-app). Android Studio with **New Flutter Project** and Kotlin as the Android language is recommended.
- Your Ottu merchant domain, used as `merchantId`: the domain you send API requests to, without `https://` (for example `sandbox.ottu.net`).
- Your [API public key](../../getting-started/authentication.md#public-key), used by the app.
- Your [API private key](../../getting-started/authentication.md#api-key-auth), used only by your server. Never put it in the app.
- The [PG code](/glossary/#term-pg-code) (`pg_code`) of the payment gateway to pay with. See [Payment Methods](../payment-methods.md) to find yours.

## Installation

In `pubspec.yaml`, add the SDK under `dependencies`:

```yaml
ottu_flutter_checkout:
  git:
    url: https://github.com/ottuco/ottu-flutter.git
    ref: 2.2.7
```

Then download it:

```bash
flutter pub get
```

If you use CocoaPods, use release version **2.2.7-cocoapods**.

## Create a Payment Session

Your server calls the [Checkout API](../checkout-api.mdx) with your [private key](../../getting-started/authentication.md#api-key-auth). The response contains the `session_id`; send it to the app together with the amount, because the SDK needs both.

If the call fails, the response has no `session_id`. A `401` means the key is missing or wrong, for example the public key was sent instead of the private key. A `400` means a required field such as `amount`, `currency_code` or `pg_codes` is missing or invalid. See [Error Codes](../../reference/error-codes.md) for the error response format.

## Add OttuCheckoutWidget

In the screen that shows the checkout, import the SDK and add `OttuCheckoutWidget` with its `CheckoutArguments`:

```dart
import 'package:ottu_flutter_checkout/ottu_flutter_checkout.dart';
```

```dart
OttuCheckoutWidget(
  arguments: CheckoutArguments(
    merchantId: "sandbox.ottu.net", // your Ottu merchant domain
    apiKey: "your API public key",
    sessionId: "the session_id from your server",
    amount: 10.0, // the session amount
    showPaymentDetails: true,
    paymentOptionsDisplaySettings: PaymentOptionsDisplaySettings(
      mode: PaymentOptionsDisplayMode.BOTTOM_SHEET,
      visibleItemsCount: 5,
    ),
  ),
),
```

All the arguments above are required, and the widget sets its own height. To choose the payment methods shown, add [`formsOfPayment`](flutter.mdx#display-options). To start faster, pass the session details with [`setupPreload`](flutter.mdx#preloading).

## Callbacks

Pass `successCallback`, `cancelCallback` and `errorCallback` to the widget. Each one receives the result as a message string. This example shows it in a dialog:

```dart
OttuCheckoutWidget(
  arguments: checkoutArguments, // the CheckoutArguments shown above
  successCallback: (message) => _showResult("Success", message),
  cancelCallback: (message) => _showResult("Cancel", message),
  errorCallback: (message) => _showResult("Error", message),
),

void _showResult(String title, String message) {
  showDialog<void>(
    context: context,
    builder: (BuildContext context) {
      return AlertDialog(
        title: Text(title),
        content: SingleChildScrollView(child: Text(message)),
        actions: <Widget>[
          TextButton(
            child: const Text('Close'),
            onPressed: () => Navigator.of(context).pop(),
          ),
        ],
      );
    },
  );
}
```

See [Callbacks](flutter.mdx#callbacks) for how the callbacks work on Android and iOS.

## Test a Payment

Run the app with `flutter run` (or the Run button in your IDE) and pay with a test card for the gateway in your session's `pg_codes`. When the payment succeeds, `successCallback` is called.

- [Ottu Sandbox](../ottu-sandbox.mdx): a simulated gateway where the [test card](../ottu-sandbox.mdx#test-cards) decides the result.
- [Test Cards](../sandbox.mdx): test cards for each payment gateway's own sandbox.
