The Checkout SDK is a Flutter framework (library) developed by Ottu, designed to seamlessly integrate an Ottu-powered [checkout process](../) into Flutter applications for both iOS and Android platforms. This framework functions as a wrapper over the corresponding native SDKs, ensuring a smooth and efficient payment experience.

With the Checkout SDK, both the visual appearance and the forms of payment available during the checkout process can be fully customized to meet specific requirements.

To integrate the Checkout SDK, the library must be added to the Flutter application and initialized with the following parameters:

- [merchant_id](flutter.mdx#merchant_id-string)
- [session_id](../../checkout-api)
- [API key](../../../getting-started/authentication#public-key)

Additionally, optional configurations such as the [forms of payment](../) to be accepted and the [theme](../) styling for the checkout interface can be specified.

## Installation

### Prerequisites

#### Android

The SDK can be used on devices running **Android 8 (Android SDK 26)** or higher.

:::warning

To prevent application crashes, it must be ensured that the correct parent theme is applied to the Android application. The theme configuration is defined in the `themes.xml` and/or `styles.xml` files located within the `res/values` directory. The `parent` attribute of the `style` tag should be set to `Theme.Material3.DayNight.NoActionBar`.

For reference, the configuration file can be reviewed at the following link: [themes.xml on GitHub](https://github.com/ottuco/ottu-flutter/blob/main/Sample/android/app/src/main/res/values/themes.xml#L3C58-L3C94)
:::

#### iOS

The SDK can be used on devices running **iOS 15** or higher.

### SDK Integration Process

#### Android

To integrate the SDK into an Android app, you should go through the following steps:

1. From the root directory of the project open android folder and open this gradle file `app/build.gradle` (for Groovy) or `app/build.gradle.kts` (for Kotlin).
2. At the bottom of this file add the following lines:

   ```kotlin
   allprojects {
     repositories {
       maven { url = uri("https://www.jitpack.io") }
     }
   }
   ```

3. Please note, OttuSdk requires these properties of the android build script. `compileSdk` has to be 37 or newer and `minSdk` is 26. Set them if they differ.
4. Go to the android part and open `MainActivity` or your Android Activity and verify if it extends `FlutterFragmentActivity`. This Activity is usually located at the path `android/app/src/main/kotlin/<your.app.package>/` (but it may be `java` instead of `kotlin`).

   ```kotlin
   import io.flutter.embedding.android.FlutterFragmentActivity

   class MainActivity : FlutterFragmentActivity()
   ```

5. Also, check whether your app theme uses a Material theme. If not, extend it with `Theme.Material3.DayNight`. Pay attention, if you define the night theme also you should update it accordingly.

   ```xml
   <style name="LaunchTheme" parent="Theme.Material3.DayNight">
       <item name="android:windowBackground">@drawable/launch_background</item>
   </style>
   ```

6. Run the App. It is mandatory do this from a command line with this command: `flutter run`. If you set all dependencies right the App should start without any errors.

#### iOS

To integrate the SDK into an iOS app, the following steps are required:

1. Open Xcode.
2. Select “Open project” and choose a `xcworkspace` located in the `ios` directory inside the root directory of your newly created app.
3. Choose the `Runner` target and click on the General tab.
4. Find Minimum Deployments section and set value to 15.
5. The first time, run the App from terminal with the same command `flutter run`. This should create all needed files for iOS plugin registrant.

##### CocoaPods Setup

To integrate the ottu-flutter iOS plugin via CocoaPods, please follow the steps below:

1. First we need to turn off SPM globally. For this purpose we should run this command in terminal `flutter config --no-enable-swift-package-manager`
2. Next, complete the [Prerequisites](#prerequisites) and [Flutter Setup](#flutter-setup) steps above.
3. In addition to the documentation Installation chapter we also need to turn off SPM in pubspec.yaml file like this:

   ```yaml
   flutter:
     config:
       disable-swift-package-manager: true
   ```

4. Note that the CocoaPods Flutter SDK reference ends with the suffix `-cocoapods`. Add it to the repository reference as well, like this:

   ```yaml
   ottu_flutter_checkout:
     git:
       url: https://github.com/ottuco/ottu-flutter.git
       ref: 2.3.0-cocoapods
   ```

5. Now go to the `ios` directory of the project and modify `Podfile`. Run `cd ios` command in Terminal and open Podfile there.
6. At the top of the file, check if you have the line: `platform :ios, '15.0'` uncommented.
7. Then, at the line below, specify this property: `use_modular_headers!`
8. After, scroll to the bottom to the target script and add `:linkage => :static` argument to the `use_frameworks!` command, like this:
   `use_frameworks! :linkage => :static`
9. At the line below we should add the ottu_checkout_sdk pod reference, for example:
   `pod 'ottu_checkout_sdk', :git => 'https://github.com/ottuco/ottu-ios.git'`
10. Finally run the `pod install` command in Terminal, like this:
    `pod install --repo-update`
11. Now proceed with [SDK Configuration](flutter.mdx#sdk-configuration).

:::tip[Existing projects: static dependency error]
For the existing projects in case you specified pods before you might face compilation error. Please find some common workarounds below to fix them.

If you see an error while executing the command `pod install --repo-update`:

```text
[!] The 'Pods-Runner' target has transitive dependencies that include statically linked binaries: (ottu_checkout_sdk)
```

You will need to omit the transitive dependency. Add the following script above `post_install do |installer|`.

```ruby
pre_install do |installer|
  Pod::Installer::Xcode::TargetValidator.send(:define_method, :verify_no_static_framework_transitive_dependencies) {}
end
```
:::

:::tip[Xcode: non-modular header error]
If you see an error like:

```text
Lexical or Preprocessor Issue (Xcode): Include of non-modular header inside framework module
```

You will need to modify your Xcode project.
So, open Xcode project from the ios directory and select project in the Navigator pane.
Next, click on `Build Settings` tab, search for `Allow Non-modular Includes In Framework Modules` and choose `Yes` property.
Do the same steps for your `Target`.
:::

## Initialization

### Activate Payment Gateway Codes

Activate the payment gateways (`pg_codes`) you intend to use. Ensure all desired `pg_codes` are set to **active** status in your configuration. These codes are passed to the [Checkout API](../checkout-api.mdx) to determine which payment methods the customer can choose from.

### Workflow

The single most important concept: **with the Ottu Sandbox you choose the result of a payment in advance.** Every test starts by creating a session against your Sandbox `pg_code`:

## Callbacks

It is not necessary to modify anything for the callbacks, as they are managed by the native SDK.

It is needed to add a section like below in a `*.dart` file of the app:

```dart
OttuCheckoutWidget(
  arguments: widget.checkoutArguments,
  verifyPayment: _verifyPayment,
  successCallback: (message) => _handleSuccess(message),
  cancelCallback: (message) => _handleCancel(message),
  errorCallback: (message) => _handleError(message),
),

void _handleSuccess(String message) {
  _checkoutMessage.value = ("Success", message);
}

void _handleCancel(String message) {
  _checkoutMessage.value = ("Cancel", message);
}

void _handleError(String message) {
  _checkoutMessage.value = ("Error", message);
}
```

| 401 | Unauthorized | Authentication failed — missing, invalid, or expired API key or credentials. |

## Sandbox & Testing

| Option | URL | Best for |
|--------|-----|----------|
| **Shared sandbox** | `sandbox.ottu.net` | Quick tests — all gateways active, public credentials available |
| **Your own instance** | `<your-domain>.ottu.net` | Integration testing — verify your specific MID and gateway configuration |

**Recommended workflow:** Start with the shared sandbox for rapid prototyping, then switch to your own instance to test with your actual gateway configuration before going live.

For test card numbers per gateway, see [Sandbox & Test Cards](/developers/payments/sandbox/).

- [**Ottu Sandbox**](/developers/payments/ottu-sandbox) — Simulate full payment outcomes (success, failure, refunds, tokens, recurring, authorizations) end-to-end with Ottu's built-in simulated gateway
