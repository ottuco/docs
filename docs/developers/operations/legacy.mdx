# Operations v2

New integrations use [Operations v3](/developers/operations-v3). The page below describes Operations v2, which keeps working for existing integrations.

| Page | What it covers |
|---|---|
| [Operations v2](/developers/operations) | Refund, capture, void, cancel, expire and delete through one endpoint, with the v2 answers and errors. |

## Coming from v2?

Operations v3 has one endpoint per operation, requires an `Idempotency-Key` on capture, refund and void so a retry never acts twice, answers with the payment event, and uses one error format. A pending refund is `refund_pending` instead of `refund_queued`. [Here is how to migrate](/developers/operations-v3#differences-from-v2): every difference from v2, side by side.
